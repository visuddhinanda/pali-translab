# 翻译风格配置

> skill 自动读取的固定文件（`knowledge/style.md`）。
> 所有 translate / review / revise / evaluate 步骤都会读入。

---

## 一、目标读者与语体

- **目标读者**：混合受众——兼顾佛学研究者和一般读者的可读性
- **语体**：现代书面汉语，通顺自然
- **句长偏好**：自然，跟随原文节奏，不刻意控制
- **人称与口吻**：第三人称叙述

### ⚠️ 必须现代汉语，严禁文言/半文半白（硬约束）

巴利义注原文是古典文体，**但译文必须是现代书面汉语**，不得译成文言或半文半白。下面是**禁止**的文言写法与对应的现代改法：

| 禁（文言/半文半白） | 改（现代书面汉语） |
|---|---|
| 注曰、曰、云 | 说、说道、解释说 |
| 年方七岁 | 七岁时 |
| 身着盛装 | 穿着华丽的衣服 |
| 端坐父膝 | 端正地坐在父亲膝上 |
| 在家用膳毕 | 在家吃完饭后 |
| 于…之际、当…之时、在…之际 | 在…的时候、当…时 |
| 即证阿罗汉果 | 就证得了阿罗汉果 |
| 答以“是” | 回答说“是” |
| 端坐（父膝/寺中） | 端正地坐着（在父亲膝上／在寺院里） |
| 身着盛装、盛装打扮 | 穿着华丽的衣服、打扮得很漂亮 |
| 便（=于是）、遂 | 就、于是 |
| 用膳 | 吃 |
| 此类人、此人 | 这样的人、这个人 |
| 此中、故为、彼等、是故、若…则 | 这里、因此是、他们、所以、如果…就 |
| 谓、乃、之、其、以、所（作文言虚词时） | 用现代对应词或直接省略 |

**总原则**：能用双音节现代词就不用单音节文言词（之/其/乃/便/即/於/遂…）；不用文言句式（…者，…也／于…之际／经…后）。

**判定标准**：把译文读给一个没有古文基础的现代读者，若有任何一句让他觉得"像古文/像文言"，即不合格。宁可句子长一点、白一点，也不要文雅化、文言化。

## 二、术语处理策略

### 混合策略

- **常见术语**用传统汉译：世尊、比丘、舍利弗、涅槃、四圣谛、八正道等
- **罕见或有争议的术语**用巴利音译，首次出现附简注
- **法相术语**：首次出现夹注巴利原词（圆括号），其后只用汉译
- **数字法门**：固定译法见 `terms.md`

### 未定译名

- 遇到 `terms.md` 未登记的术语：
  - 优先沿用传统汉译（南传常见译法 / 元亨寺 ）
  - 若多家译法不一，选最有依据的一个译出，**不在译文里留标记**；把该句 `confidence` 调低，
    分歧写进 review / evaluate 的报告，定案后补进 `terms.md`

---

## 三、原文显示

- **显示巴利原文**：否
- **显示缅文 nissaya**：否
- **夹注格式**：术语首次出现用圆括号附巴利原词，如"沙门（samaṇa）"

---

## 四、注释与详释

- **详释段**：译为段后小字注释
- **句法注（`[...]`）**：作为译者参考，不进正文译文
- **异释（`ဝါ=`）**：取主译，异释作脚注备列

详见 skill 自带 `references/nissaya_format.md`。

---

## 五、标点与格式

- **标点系统**：一律用中文全角标点（，。、；：！？（）—— 等）。
- **引号**：双引号一律用全角 “”，单引号用全角 ‘’（夹注巴利原词的括号用全角圆括号）。**不要用直角引号「」『』**，统一为弯引号 “” ‘’。
- **硬约束（JSON 安全）**：译文 `zh` 字段内**严禁出现 ASCII 双引号 `"` 或单引号 `'`**——译文要先经逐行 JSON 传给 wikipali 写入环节，字段值本身由 ASCII 双引号包裹，内部再出现 ASCII 引号会使整行 JSON 非法、该句被丢弃、漏写进 channel。需要引号时一律用全角 “” ‘’。
- **段落切分**：依巴利原文段，不合并不拆分
- **偈颂处理**：保留分行，不强制字数对齐

---

## 六、不做什么

- 不擅自补足省略主语（除非语义必须）
- 不用现代政治/心理学术语对译法相
- 不直译为半通不通的"翻译腔"，宁可意译

---

## 七、信心标记

- **译文里不留任何工作标记**（候选、待定、问号、TODO）。写进 channel 的是给读者看的译文，
  不是草稿——不确定就压低该句 `confidence`，存疑写进 review / evaluate 的报告
- 信心指数尺度：0–100（数值）
